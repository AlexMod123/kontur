# КОНТУР-ПРО v18.0 «Квант+ Commercial»

Пакет `kontur` (Python 3.12) для инженерного проектирования систем здания:
электроснабжение, заземление и молниезащита, освещение, климат (охлаждение/
вентиляция/теплопотери), ЛВС/СКС с PoE, а также слаботочные системы
безопасности — СКУД, ОПС и видеонаблюдение. Расчёт выполняется по шаблону
здания (Офис/Склад/ЦОД/Школа) и уровню отказоустойчивости (Tier I–III), либо
по проекту, загруженному из `.kontur`-файла или импортированному из DXF.

Что считается (и по какой норме):

- **Электроснабжение** — мощности, ток, сечение кабеля и автомат, падение
  напряжения, баланс фаз, селективность автоматов (ПУЭ 7, СП 256.1325800)
- **Токи короткого замыкания** — 3-фазный, 1-фазный, ударный (ГОСТ 28249)
- **Заземление и молниезащита** (СО 153-34.21.122-2003)
- **Утечки тока и подбор УЗО** (СП 256.1325800)
- **Освещение** — методом коэффициента использования (СП 52.13330)
- **Климат** — охлаждение, вентиляция, теплопотери (СП 50.13330)
- **Акустика** — уровень шума оборудования (СНиП 23-03-2003)
- **ЛВС/СКС** — порты, кабель, патч-панели, бюджет PoE (ГОСТ Р 53246, IEEE 802.3)
- **ИБП** — мощность и автономия с учётом Tier-резервирования
- **Кабельный журнал** (ГОСТ 21.613) и **спецификация оборудования** (ГОСТ 21.110)
- **Позиционные обозначения** (ГОСТ 2.710-81) и трассировка кабеля (A*)

## Быстрый старт

Требуется [mise](https://mise.jdx.dev/) (сам ставит Python 3.12 и создаёт `.venv`).

```bash
mise install          # поставить Python 3.12
mise run install      # editable-установка kontur[dev,excel,pdf,dxf]
mise run demo         # python -m kontur --cli --template ЦОД --tier 3
```

Без mise — обычным pip:

```bash
python -m venv .venv
source .venv/bin/activate         # Windows: .venv\Scripts\activate
pip install -e '.[all]'           # все опциональные форматы + GUI
# или точечно: pip install -e '.[excel,pdf,dxf]' / '.[dev]'
```

После установки (в т.ч. через mise) в `.venv` появляется консольная команда
`kontur` (entry point `kontur.cli:main`, см. `pyproject.toml`).

## Использование CLI

```bash
python -m kontur [флаги]      # или: kontur [флаги]   (после установки пакета)
```

| Флаг | Назначение |
|---|---|
| `--cli` | явный CLI-режим (без него и без других флагов запускается GUI) |
| `--gui` | явный GUI-режим (требует установленный экстра `gui`) |
| `--template ИМЯ` | шаблон здания: `Офис` (по умолчанию), `Склад`, `ЦОД`, `Школа` |
| `--tier {1,2,3}` | уровень отказоустойчивости (по умолчанию 1) |
| `--export` | экспорт во все доступные форматы |
| `--output-dir ПУТЬ` | каталог для экспортируемых файлов (по умолчанию текущий) |
| `--save ФАЙЛ` | сохранить рассчитанный проект в `.kontur` |
| `--load ФАЙЛ` | загрузить проект из `.kontur` вместо шаблона |
| `--import ФАЙЛ` | импортировать план из DXF (нужен `ezdxf`) |
| `--floor N` | этаж (по умолчанию 1) |
| `--outdoor T` | уличная температура, °C, для расчёта теплопотерь (по умолчанию −28) |
| `--test` | запустить весь набор unit-тестов из `tests/` |
| `-h`, `--help` | справка |

Примеры:

```bash
# базовый расчёт по шаблону и tier
kontur --cli --template Офис --tier 1
kontur --cli --template Школа --tier 2

# экспорт всех форматов в указанный каталог
kontur --cli --template ЦОД --tier 3 --export --output-dir ./out

# сохранение и загрузка проекта
kontur --cli --template Склад --tier 1 --save sklad.kontur
kontur --load sklad.kontur

# импорт плана из DXF (AutoCAD/nanoCAD) с последующим экспортом
kontur --import plan.dxf --export

# теплопотери для другой уличной температуры
kontur --cli --template Офис --outdoor -35
```

Коды завершения: `0` — успех; `1` — GUI недоступен (нет PyQt6) или
`--test` завершился неуспешно; `2` — ошибка входных данных (не найден или
повреждён файл `.kontur`/DXF).

Обратная совместимость со старым монолитом: `python kontur_v18.py ...` —
тонкая обёртка, делегирующая в `kontur.cli:main` (см. `kontur_v18.py`).

GUI (PyQt6) запускается флагом `--gui` либо без аргументов вообще; требует
экстра `gui` (`pip install -e '.[gui]'` или `mise run install:all`). Без
PyQt6 `--gui` печатает понятное сообщение и подсказку по CLI-режиму, вместо
падения с `ImportError` (код возврата `1`).

### Сборка бинарника на Apple Silicon

PyInstaller собирает бинарник под архитектуру интерпретатора. Если `mise`
установлен как x86_64 (Intel Homebrew в `/usr/local`), он ставит x86_64 Python,
который на arm64-Mac работает через Rosetta, и `mise run compile` падает на
`lipo`/`xcrun` (`missing compatible architecture`). Проверка:

```bash
file "$(command -v mise)"            # должно быть arm64
mise exec -- python -c "import platform; print(platform.machine())"  # arm64
```

Решение — нативный arm64 `mise` (`/opt/homebrew/bin/brew install mise` или
`curl https://mise.run | sh`), затем пересоздать окружение:
`mise uninstall python@3.12 && rm -rf .venv && mise install && mise run install`.

## Архитектура

```text
kontur/
  config/            конфигурация: нормы, шаблоны/Tier, оборудование, темы, версия
  models.py          датаклассы предметной области (Device, Room, Wall, Door,
                     Annotation, CableTrace, EngineeringResult)
  calculators/        15 инженерных калькуляторов по доменам (electrical,
                     short_circuit, grounding, climate, lighting, acoustic,
                     network, journal)
  routing.py         A*-трассировщик кабеля (8 направлений, heapq)
  scale.py           перевод пиксели <-> метры
  designation.py     позиционные обозначения (ГОСТ 2.710) и УГО
  core.py            EngineeringCore — конвейер расчёта (17 шагов)
  checker.py         ModelChecker — реестр правил проверки на соответствие нормам
  specification.py   спецификация оборудования (ГОСТ 21.110) + база вендоров
  report.py          рендеринг текстового отчёта CLI (чистая функция)
  export/            экспорт в JSON/HTML/TXT/Excel/PDF/DXF (Strategy + Registry)
  persistence/        ProjectManager (.kontur), DXFImporter, ExternalCatalog
  twin/              цифровой двойник (графовая модель, билдер, импорт Canvas/Figma)
  templates.py        генерация устройств/помещений по шаблону здания
  multiproject.py    сравнение нескольких рассчитанных проектов
  undo.py            UndoManager (undo/redo с ограниченной историей)
  cli.py             argparse-парсер и конвейер CLI (main)
  gui.py             GUI на PyQt6 (опционально, лениво импортируется)
  __main__.py        точка входа `python -m kontur`
```

Направление зависимостей: `config` → `models` → `calculators`/`routing`/`scale` →
`core` → `report`/`export`/`persistence`/`checker` → `cli`/`gui`. Модули выше по
цепочке не импортируют модули ниже.

Использованные паттерны:

- **Strategy + Registry** — каждый формат экспорта (`kontur/export/*_export.py`)
  реализует абстрактный `ExportFormat` и регистрируется декоратором
  `@register` в `kontur/export/registry.py`; `export_all()` перебирает реестр.
- **Facade** — класс `Exporter` в `kontur/export/__init__.py` сохраняет старый
  статический API (`to_json`, `to_html`, ...) поверх стратегий, ради обратной
  совместимости с `cli.py`/`gui.py`.
- **Registry правил проверки** — `ModelChecker` выполняет список функций
  `CheckRule` из `DEFAULT_RULES` (`kontur/checker.py`) по порядку.
- **Pipeline / Template Method** — `EngineeringCore.calculate()`
  (`kontur/core.py`) прогоняет список из 17 шагов `_step_*`, каждый дополняет
  общий `EngineeringResult`.
- **Factory** — `generate_template()` (`kontur/templates.py`) строит
  устройства и помещения по декларативным таблицам `ROOM_DEVICE_SPECS`/
  `SERVER_ROOM_SPECS` и словарю `TEMPLATES`.
- **Chain of Responsibility (миграции схемы)** — `ProjectManager._migrate()`
  (`kontur/persistence/project.py`) применяет упорядоченный список
  `SCHEMA_MIGRATIONS` к загружаемому `.kontur`-файлу.
- **Атомарная запись** — `_atomic_write_json()` пишет во временный файл в той
  же директории и переименовывает (`os.replace`), плюс резервная копия перед
  перезаписью существующего проекта.

## Шаблоны и Tier-уровни

Фактические числа (проверены по `kontur/config/building_templates.py` и
генератору `kontur/templates.py`; в старой инструкции по сборке монолита эти
цифры были другими и устарели):

| Шаблон | Площадь (`floor_area`), м² | Помещений | Устройств (сгенерировано) | Особенности |
|---|---|---|---|---|
| Офис | 445 | 6 | 51 | ПК, IP-камеры, СКУД, ОПС, серверная |
| Склад | 1285 | 5 | 51 | Зоны хранения и разгрузки, СКУД, ОПС, серверная |
| ЦОД | 570 | 5 | 43 | Машинные залы, электрощитовая, ДГУ, серверная |
| Школа | 620 | 7 | 86 | Кабинеты информатики (много ПК), актовый зал, столовая |

Во всех шаблонах серверная (`server_room: true`) добавляет фиксированный
комплект: стойку 42U, коммутатор 48p PoE+ и NVR. Набор устройств в каждом
помещении задаётся одинаково для всех шаблонов (`ROOM_DEVICE_SPECS`): ПК,
IP-камеры, контроллер+замок СКУД, панель ОПС и 2 дымовых извещателя — состав
не зависит от типа здания (PTZ-камер и тепловых извещателей генератор не
создаёт, несмотря на упоминания в старой инструкции).

Tier задаёт схему резервирования ИБП, целевую автономию и резерв охлаждения (`TIER_CONFIG`):

| Tier | Схема ИБП | Целевая автономия | Резерв охлаждения | Описание |
|---|---|---|---|---|
| I | N | 10 мин | ×1 | Базовый, без резервирования |
| II | N+1 | 15 мин | ×2 | N+1 резервирование |
| III | 2N | 15 мин | ×2 | Конкурентное обслуживание, 2N |

Подбор ИБП (`EngineeringCore._step_ups`): модульный ИБП по 5 кВт на модуль,
`n = ceil(P_расч / 5 кВт)`; установлено `n` / `n+1` / `2n` модулей для N / N+1 / 2N.
АКБ — блоки 12 В × 100 А·ч (1200 Вт·ч), КПД инвертора 0.9, используемая доля
ёмкости 0.8; число блоков на линию подбирается под целевую автономию, для 2N —
две независимые линии. Отчёт показывает автономию одной линии при полной
нагрузке (консервативно). Эти параметры — проектные допущения, заданы
константами в `kontur/core.py`.

На количество генерируемых устройств `--tier` не влияет (параметр
зарезервирован в `generate_template()`).

## Разработка

Тесты лежат в `tests/`: по одному файлу на область пакета (калькуляторы,
балансировка фаз, токи КЗ, checker, CLI, core, export, persistence, роутинг,
twin, мелкие модули), и отдельно
`tests/golden/` — эталонные текстовые снимки CLI-вывода
(`cli_<Шаблон>_tier<N>.txt`), сверяемые в `tests/test_golden.py` побайтово
через реальный запуск `python -m kontur --cli --template ... --tier ...`.

Если инженерный расчёт намеренно меняется (не регрессия, а осознанная
правка формулы), обновите нужный эталон явно:

```bash
python -m kontur --cli --template Офис --tier 1 > tests/golden/cli_Офис_tier1.txt
```

и проверьте получившийся diff перед коммитом — golden-тест защищает именно
от случайных изменений вывода, а не запрещает осознанные правки.

Проверка качества:

```bash
mise run lint        # ruff check
mise run typecheck    # mypy
mise run test         # pytest (включая golden)
mise run check        # CI-гейт: lint + typecheck + test
```

Стиль кода:

- везде аннотации типов (`from __future__ import annotations`, mypy в CI);
- в библиотечном коде (`calculators/`, `core.py`, `checker.py`, `export/`,
  `persistence/`, ...) — только `logging`, без `print()`; `print()` допустим
  исключительно в `cli.py` (вывод пользователю);
- опциональные зависимости (`openpyxl`, `reportlab`, `ezdxf`, `PyQt6`)
  импортируются лениво внутри функций/методов, а не на уровне модуля;
  доступность проверяется через `importlib.util.find_spec` в
  `ExportFormat.is_available()`, что позволяет пакету работать без них.

## Инженерные исправления после рефакторинга

При переносе монолита в пакет найдены и исправлены ошибки расчёта (эталоны
`tests/golden` перегенерированы осознанно):

- **ИБП.** Автономия раньше считалась от фиксированных 100 Вт·ч (0.5 мин для ЦОД
  Tier III), число АКБ не учитывало резервирование, Tier II («N+1») фактически
  считался как 2N. Теперь — модульный подбор по схеме Tier и АКБ под целевую
  автономию (см. раздел о Tier).
- **Длина кабеля.** `_avg_cable_length` делил расстояние на масштаб дважды —
  длины были в 50 раз меньше, падение напряжения ≈0.01%. Теперь
  манхэттенское расстояние щит–устройство, пересчитанное в метры один раз.
- **Балансировка фаз.** Нагрузки от 4 кВт (`THREE_PHASE_MIN_POWER_W`, например
  стойка 42U) подключаются трёхфазно и делятся поровну; остальные раскладываются
  по току (LPT) с последующим улучшением перестановками. `imbalance_pct` больше
  не игнорирует пустую фазу (раньше `{A: 10, B: 0, C: 0}` давало 0%). Перекос ЦОД
  63.5% → 0%.
- **Токи КЗ (ГОСТ 28249-93).** Вместо фиксированных 0.1 Ом источника —
  сопротивление трансформатора (`SourceImpedance.from_transformer`, по
  умолчанию ТМГ-400/10: S = 400 кВА, uk = 4.5%, ΔPк = 5.5 кВт) и сети
  (Sкз = 200 МВА). Однофазный ток — по петле фаза–нуль. Неиспользуемые
  параметры `ups_power_w` и `cos_phi` удалены из API.
- **Трёхфазный ввод.** Автомат и вводной кабель подбирались по сумме токов
  трёх фаз из таблицы однофазных кабелей `3xS` — ток завышался втрое (Школа:
  84 А, С125, 3×16). Теперь расчётный ток ввода — ток наиболее нагруженной фазы
  с учётом cos φ (для симметричной нагрузки = P / (√3·U·cos φ)), кабель
  пятижильный `5xS` по ПУЭ-7 табл. 1.3.6 (графа «трёхжильные»,
  `CABLE_TABLE_3PH`), номинал автомата не превышает допустимый ток кабеля
  (иначе сечение увеличивается). Школа: 30.4 А, С40, 5×6. Проверка «Сечение
  кабеля» в ModelChecker теперь реальная. `CABLE_TABLE` (`3xS`) остаётся для
  однофазных групповых линий (кабельный журнал).
- **JSON-экспорт.** Трассы кабелей сериализуются как объекты
  (`device_id`, `path`, `length_m`, `system`, `vertical_length`), а не как `repr`.

## Известные ограничения

- Модель КЗ не учитывает сопротивление дуги и переходные сопротивления
  контактов, которые ГОСТ 28249 рекомендует учитывать; нулевой проводник
  принят того же сечения, что и фазный.
- Падение напряжения и ток КЗ считаются по средней длине линии, а не по
  самому удалённому потребителю.
- Фазные токи округляются до 0.1 А до расчёта тока ввода.
- Вводной кабель выбирается по току нагрузки; мощность входа ИБП и
  поправочные коэффициенты на способ прокладки и группировку не учитываются.

### Изменения поведения относительно монолита v18

Осознанные изменения, не затрагивающие расчёты:

- CLI возвращает коды выхода: `0` — успех, `1` — провал тестов или нет PyQt6,
  `2` — ошибка входных данных (битый DXF, отсутствующий `.kontur`).
  `run_cli()` теперь возвращает код выхода, а не `EngineeringResult`.
- Аргументы проверяются строго во всех режимах: неизвестный флаг даёт ошибку
  argparse даже вместе с `--test`/`--gui`.
- `--export` пишет все 6 форматов с одной меткой времени в `--output-dir`.
- HTML-экспорт экранирует имена устройств и помещений (`html.escape`).
- `ExternalCatalog.import_csv` пропускает некорректные строки с предупреждением
  в лог вместо отказа от всего файла; `-1` — только если файл не читается.
- `TwinImporter.parse` пропускает узлы/группы без `id` вместо падения.
- Сохранение `.kontur` и `catalog.json` атомарное (временный файл + `os.replace`).
